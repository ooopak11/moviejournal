# 서버와 Docker 기초 (이 프로젝트 기준)

## 핵심 결론

- 네, BookStack은 동적 웹앱이라 **서버 프로세스 + 데이터베이스가 항상 실행**되어야 접속 가능하다.
- 다만 그 서버가 꼭 “내 PC”일 필요는 없다.
- Docker는 서버를 대체하는 게 아니라, 서버 위에서 앱을 실행하기 쉽게 만드는 포장/실행 방식이다.

## 왜 서버가 필요한가

이 사이트는 정적 HTML 묶음이 아니라, 요청마다 앱이 처리한다.

- 로그인/세션 관리
- 권한 체크(Editor/Viewer 등)
- 페이지 생성/수정/검색
- 변경 이력(Revision) 저장

이 작업을 하려면 웹앱(BookStack)과 DB(MariaDB)가 살아 있어야 한다.

## Docker를 안 쓸 때와 쓸 때

1. Docker 없이
- 서버에 PHP, Nginx, MariaDB를 직접 설치/설정
- 버전 충돌과 환경 차이 대응이 어렵다

2. Docker 사용
- `docker-compose.yml`로 앱+DB를 한 번에 실행
- 다른 PC/서버로 옮겨도 재현성이 높다
- 중지/재시작/백업 절차가 단순하다

## 지금 구조에서의 실제 의미

- `moviejournal_bookstack` 컨테이너: 웹앱
- `moviejournal_db` 컨테이너: 데이터베이스
- 두 컨테이너가 꺼지면 사이트도 사실상 꺼진다.

## 운영 시나리오

1. 로컬 개발/테스트
- 내 PC에서 Docker 실행
- 내 PC가 켜져 있을 때만 접속 가능

2. 팀 내부 상시 사용
- 항상 켜진 서버(VPS/클라우드/미니PC)에 Docker Compose 배포
- 서버가 켜져 있으면 언제든 접속 가능

3. 공개 운영 전 단계 권장
- 로컬 검증 후, 저렴한 VPS 1대에 올려 내부 베타 운영

## 한 줄로 정리

동적 사이트는 “항상 실행 중인 서버”가 필요하고, Docker는 그 서버 운영을 쉽게 만드는 도구다.
